Voxcade is a voxel arcade engine. Everything is made of little cubes,
everything can be blown apart, and it has to feel like an arcade machine.
The plan: the classic 2D genres, rebuilt in voxels — with an AI agent at
your side that can see, test and change what you build. It is two weeks
old, the repository is still private and there is nothing to download
yet — but there is enough to tell.

# Where it comes from

[Voxatron](https://www.lexaloffle.com/voxatron.php) proved the idea: a
whole world of destructible voxels, small games, instant fun. It never
left alpha and is no longer developed. Voxcade keeps the idea and the
feel, not the implementation, and changes three things:

- **The world fills the screen** instead of floating in a box.
- **The GPU does the drawing.** Rust and wgpu, on Vulkan, Metal or
  DirectX 12; SDL3 for the window, gamepads and sound.
- **Open formats, own editors.** Models are MagicaVoxel `.vox` files and
  levels are plain JSON, so the voxel editor you already use works. The
  IDE brings its own voxel and level editors as well, and Tiled maps come
  in with one import.

# The look

One fixed camera per game, in perspective, that only moves across the
ground. A top-down RPG, a 2.5D jump & run and an arena shooter are just
different angles. The figures are small and plain — 10 to 20 voxels tall,
one colour per material, every voxel deliberate: the 8-bit charm in clean
cubes. The engine does the light and the shade, sun shadows included, and
a model can be lit voxel by voxel like pixel art, so a round shape shades
softly and only its outline stays blocky.

And things break the way they look. After a blast the debris settles back
into the world, and whatever no longer connects to the ground falls.

# A game is a folder

After [LÖVE](https://love2d.org/): `conf.lua` sets the game up,
`main.lua` is the game.

```lua
function on_level_start(how)              -- the level begins
  level:fill(0, 0, 0, 127, 127, 0, "#3b4150")   -- a floor
  level.state.keeper = level:spawn("keeper", 64, 64)
  level.camera:look_at(64, 64)
end

function on_tick()                        -- 60 times a second
  local keeper = level.state.keeper
  keeper:walk(input.dir, 40)
  if input:pressed("jump") then keeper:jump(8) end
end
```

Every length is in voxels, every speed in voxels per second. Whoever
prefers Rust uses the engine as a library instead.

# Built for agents

The goal from the first commit: anyone should be able to write a great
game with it, and an AI agent should be able to help. That shaped the
engine as much as the cubes did.

- **Everything is text.** Rules in Lua, settings in `conf.lua`, models
  as `.vox`, levels as JSON, music as MML, sound effects as a few numbers
  each. People, agents and editors work on the same files, and the game
  plays a change the moment it is saved.
- **The API documents itself.** It ships as a Lua definition file with
  LuaLS annotations, so editors and agents get completion and checks from
  the same source, and `voxcade api` prints any part of it.
- **Seeing without a window.** `voxcade shot` plays a game with scripted
  input and saves one frame; the same command always gives the same
  picture. That is how an agent sees what it built. `voxcade inspect`
  prints how the game stands as JSON, and `voxcade film` turns a run into
  an MP4 or GIF.
- **Checking without playing.** The simulation is deterministic: seeded
  random numbers, maths that is bit-identical on Linux, Windows and macOS,
  and all game state in plain tables that are hashed every tick. So a
  replay is a test and a bug report at once, and `voxcade check` plays
  every one and says whether it still runs as recorded. The same replays
  run on the title screen in attract mode, as an arcade machine would.
- **One MCP server.** `voxcade mcp` hands an agent the frame, the
  game's state, the checks and the API as tools, and
  `claude mcp add voxcade -- voxcade mcp` is the whole setup in Claude
  Code.

The IDE goes one step further. Logic and assets on the left, one editor in
the middle, voxel and level editors beside it, PLAY and BUILD — and a
console with Claude Code in it, one conversation per game. Through the
IDE's own MCP tools the agent sees what you see: the open file and the
cursor, errors down to file, line and tick, the running frame. It can act
too: show you a file at a line, start the game and stop it. It edits
through the files, and the IDE takes its changes in.

# What plays today

A handful of small games already run on it, each in a different genre —
shooters, a jump & run, a puzzle game, a farming sim — and each there to
prove a part of the engine. One of them is written in Rust instead of
Lua, to show that the second way in works too.

Sound and music are synthesized: a SID-like synth, and songs written in
MML, a music notation an agent can write as well as a person.
